# Target clue-count experiment

`counts` is a separate structured-input experiment. It keeps the focus image and
adds four integers for the target row and column: original clue, occupied cells,
unassigned cells, and remaining track cells. Occupied cells include source givens
and the model's earlier nonempty choices. Remaining is clue minus occupied, even
if a mistaken earlier choice makes it negative. The prompt explains the two
simple deductions from [RULES.md](../../RULES.md): remaining zero means unassigned
cells in that line are empty; remaining equal to unassigned means they need track.

The source clues and given positions come from `clues.json`, generated by
`build_clue_manifest.py` from the audited puzzle records. This file contains no
solutions, labels, or future actions. The executor still offers all seven choices
and does not reject or change any model answer. Both training and rollout compute
counts from exactly the same function in `clue_state.py`. This changes the model
input relative to the plain and focus baselines, so compare it as its own variant.

Run from the repository root:

```powershell
py -3.11 modal/tools/build_clue_manifest.py
py -3.11 modal/tools/test_clue_state.py
uv run modal run modal/evaluate_puzzles.py --visual-variant counts --limit-puzzles 1
uv run modal run --detach modal/evaluate_puzzles.py --visual-variant counts
uv run modal run modal/train.py --mode smoke --visual-variant counts
uv run modal run --detach modal/train.py --mode full --visual-variant counts
uv run modal run --detach modal/evaluate_puzzles.py --run-id COUNTS_FULL_RUN_ID
```

The last command reads `visual_variant=counts` from the checkpoint's training
report. Use validation to compare whole-puzzle success, row/column count errors,
track recall, and the first wrong move. Keep test splits untouched until the
variant is frozen.

## Base-model validation result

The untrained d1-2B completed all 46 validation puzzles with `counts` input on
2026-11-11. The report is `modal/results/validation-counts-base-20261111T032011Z.json`
and the corresponding Modal Volume path is
`rollouts/validation-counts-base-20261111T032011Z.json`.

| Measure | Plain base | Counts base |
| --- | ---: | ---: |
| Whole puzzles solved | 0/46 | 0/46 |
| Correct cells | 1,070/2,472 (43.3%) | 454/2,472 (18.4%) |
| Malformed answers | 0 | 0 |
| Mean absolute row clue error | 1.81 | 2.91 |
| Mean absolute column clue error | 2.21 | 2.65 |

The counts base model predicted `NS` for 1,830 of 2,472 cells and made an
incorrect first move on 45 of 46 puzzles. This is an out-of-distribution base
test: the model has not been trained on the count fields. The `counts` variant
also includes the focus image, so this result does not isolate numerical text
from visual focus. Run the smoke training and checkpoint reload before a full
count-aware SFT run. Do not infer SFT performance from this base result.

## Smoke training and checkpoint reload

Run `d1-2b-counts-smoke-train-tracks-decisions-20261111T032353Z` completed four
optimizer steps on 16 training rows. It saved and reloaded successfully. Loss
on four validation rows fell from 2.413 to 0.956. In a one-puzzle rollout, the
checkpoint gave 61 `empty` answers, scored 34/61 cells, and solved 0/1 puzzles.
This smoke result checks pipeline operation only; its tiny, repeated training
sample cannot estimate the full SFT result. Inspect track recall and class mix
after the full run, since either all-`NS` or all-`empty` behavior is unsuitable.

## Full-run preparation fix

The first full-training attempt stopped during image mapping, before any optimizer
step. The old grid detector treated a long black track stroke as an extra grid
line. `board.py` now detects the renderer's gray `#666666` cell borders instead.
`check_grid_detection.py` checked all 11,187 training images and 2,472 validation
images: zero detection failures and no grid-coordinate drift within a puzzle.
The count-state tests and Python compile checks pass. The completed full run
used this corrected detector; the earlier smoke checkpoint predates the change.
